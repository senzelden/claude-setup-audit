# 0.15.0: full-feature restore for the repo marketplace (design)

Date: 2026-11-11. Status: approved by the user (spec and plan pre-approved, "work on your own").

## Why

Releases 0.13.1–0.14.7 removed working audit features one round at a time to clear the plugin
directory's automated holds. On 2026-11-10/11 the directory added two blanket rules for
organizations that aren't Verified: LOCAL_CODE_FILE_TYPE (only md/txt/json/yaml/images may ship) and
LOCAL_CODE_TOOL_GRANT (allowed-tools limited to Read/Grep/Glob/LS). Our organization can't become
Verified, and there is no way to apply (anthropics/claude-plugins-official#7024, 22 reports, no reply
from Anthropic). So the Python plugin can't be listed again whatever we remove. The full plugin is
distributed from this repo's own marketplace (`setup-audit@claude-setup-audit`), and the directory
will get a separate Markdown-only lite plugin later (not part of this release).

0.15.0 therefore restores what the directory rounds took out, and adds two roadmap items.

## Goals

1. Bring back every feature group removed only for the scanner (list below). Restored behaviour
   matches the last version that had it (v0.13.3 for most, v0.14.6 for `needsAuthMcpServers`,
   v0.14.6 for the secret-literal flags), and keeps every later bug fix.
2. Keep the privacy design that is good on its own merits: names-only reads through
   `config_names.py`, redaction of every snapshot string, values never written, the SKILL.md
   never-open rule for credential helper settings, metadata-only output.
3. Names-only collector fallback (new).
4. Measured outcome after apply (new).
5. Replace scanner-only bundle guards with guards for real rules.

## Non-goals

- The directory lite plugin (separate later project; see memory `project-directory-verified-org-rules`).
- README changes beyond what restored features require (user decision: README stays as is for now;
  changelog, plugin README disclosures and references must stay accurate though).
- New MCP sources, such as pasted `claude mcp list` output.
- Any change to the cosmetic 0.13.x restructuring (docs cited by page name, regexes built from named
  tuples, no `icon` field, eval suite outside the plugin, plugin-folder README). Keep it.

## Anti-goals (a failure even if tests pass)

- Any credential value (env value, header value, OAuth token, `.envrc` assignment value) reaching
  the snapshot, the report or Claude's context through a script.
- Network access from any script other than `fetch_doc.py`, or `fetch_doc.py` reaching any host
  other than `code.claude.com`.
- Losing a bug fix made in 0.13.1–0.14.7 while restoring (for example the hook fingerprint header
  fix, the fetch_doc temp-dir cleanup, the `test_mods` temp-name fix, the descriptor-chain write).
- Silent partial restore: a check id in the checklist without its snapshot field, or a snapshot
  field without schema/contract/test coverage.

## Feature groups to restore (all chosen by the user)

A. **MCP inventory** (removed 0.14.0, 0.14.5, 0.14.6): `~/.claude.json` as a source
   (`global.mcp_user`, user/local scope rows, `extensions.mcp_project_state`, approval/trust
   observations, `policy_observations` toggle kinds, `mcp_name_collisions`,
   `project_trust_accepted`); project `.mcp.json`, managed MCP and plugin MCP readers;
   `extensions.mcp_servers`, `projects[].mcp_servers`; the names/counts fields for env, headers,
   oauth and `${VAR}` references; `transcripts.mcp_configured_but_unused` and the `configured`
   flag; `needsAuthMcpServers` / `sessions_needs_auth`; checks `SEC-mcp`, `SEC-mcp-exposure`
   (all bullets), `HYG-mcp-config` (all notes, including same-name-across-scopes);
   `SEC-mcp-review` goes back to being covered by those checks. `COST-mcp-unused` uses the
   inventory again.
B. **Env + secret checks** (0.14.0, 0.14.7): `.envrc` names and `pointer_lines` /
   `literal_secret_names`, mise `[env]`, devcontainer `containerEnv`/`remoteEnv`, compose
   `environment` names counted as declared; `settings[].env_keys`; http hook `header_keys`,
   `allowed_env_vars`; `credential_mechanisms` detail; `RDY-envrc-literal-secret`;
   `secret-literal-in-rule`, `secret-via-env-file` flags, `SEC-secret-literal`,
   `SEC-secret-env`, the two `prune_permissions.py` categories, `LITERAL_SECRET_RE`,
   `privacy.contextual_search`. `RDY-env-secret-backend` comes back **opt-in only**: Claude
   asks the user each run before probing, checks set/unset only, never prints a value (this was
   already the v0.13.3 wording; make the per-run ask explicit in SKILL.md).
C. **Scope + mods** (0.14.1, 0.14.3): `HYG-scope-ignored` with `scope_ignored_keys`,
   `ignored_env_keys` including telemetry/tracing/gateway names and `telemetry_unless_off`; the
   mods inventory (`components[].mod`, `settings[].mods` from managed `pluginConfigs`) and
   `SEC-mods` with its precise call-pair wording. The 0.14.3 `js_modules_not_scanned` partial
   status remains only for module files the scanner can't read.
D. **Tooling** (0.14.2, 0.14.4): `scripts/fetch_doc.py` (fixed host `code.claude.com`, output via
   the checked descriptor chain, with the 0.14.2 test temp-dir cleanup) and Step 2 of SKILL.md
   using it, with the 0.14.4 rule kept as a fallback: if raw pages can't be saved, exact keys are
   reported unverified. `--hash-salt-file` and `coverage.privacy.hash_salt`. `apply_ops.py`
   `sandbox.credentials` writes (`credential_files`, `credential_env` value kinds, set and
   remove) and `settings[].sandbox_credentials_configured` → whatever v0.13.3 recorded.

Snapshot version: the restored fields were all present in v0.13.3 snapshots. Keep snapshot
version 1 if the contract allows additive optional fields (it did when they were removed); the
builder confirms against `snapshot_contract.py` and the schema.

## New: names-only collector fallback

When `collect.py` fails, SKILL.md today lets Claude Read `settings.json`/`.mcp.json` whole, which
brings env/header values into context. Add a script (for example `scripts/names_only.py`, name
left to the builder) that, given the same discovery roots, prints JSON with key paths, value
types, array lengths and names only (env and header names allowed, values never), redacted with
the existing `privacy` helpers. SKILL.md's fallback uses it, and Read of those files whole
becomes forbidden in the fallback. Pre-approve it in `allowed-tools` like the other scripts.
Tests: a fake home with values that must not appear in output, a malformed file, a symlinked
file (refused like the collector does).

## New: measured outcome after apply

After a proposal is applied, later audits should report what it changed, with dates. Build on
the ledger: it already supports `{"type": "metric", ...}` selectors and records a baseline.
Extend apply so that non-LRN applied proposals in the COST and SEC families that have a natural
metric (context tokens per session, cache-miss rate, permission prompts per session, allow-rule
count) get a ledger entry with a metric selector and a baseline from the snapshot used. The
next audit's report shows an "Outcome of applied fixes" section: proposal, applied date,
baseline value and window, current value and window, verdict (`dropped`, `not_dropped`,
`too_early`, `unknown`) with the existing "a verdict is a comparison of counts, not proof"
wording. Which metrics exist and how each is computed comes from snapshot fields that already
exist; the builder lists them in `references/ledger.md`. No new snapshot fields unless a metric
truly lacks one.

## Guards

Remove the guards in `tests/test_shipped_bundle.py` that exist only to dodge the scanner: URL next
to credential name, telemetry/mod-call names, credential proxy, MCP/credential pairing, salt file,
scope-ignored, mods inventory, helper-command setting names, MCP inventory, MCP config file names,
`NoSecretHuntingFlags`. Keep or rewrite as real-rule guards:
- network: only `fetch_doc.py` imports network modules, and its host is the fixed constant
  `code.claude.com` (AST check, red-proofed);
- no credential value reaches snapshot output (fake home seeded with sentinel values in settings
  env, `.envrc`, `.mcp.json` env/headers, `~/.claude.json`; assert none appear in the snapshot
  or the names-only fallback output; red-proof by disabling redaction/names-only);
- `config_names.py` is the only module that opens credential-bearing config (keep if it holds);
- `no_evals_in_plugin`, listing icon at default path, `RiskyRulePatterns` stay.

## Constraints

- Python stdlib only for tests; `python3 -m unittest discover -s tests -v` from the repo root is the
  gate, plus `claude plugin validate --strict` at both plugin and marketplace level on a clean
  export (as previous releases did).
- Tests use fake homes; nothing touches real config. No paid evals.
- No `rm -rf` (user instruction for this session); leave temp dirs for a bulk cleanup at the end.
- Commits regularly, explicit paths, trailer `Assisted-by: Claude:claude-opus-5-5`.
- Don't push, tag remotely or create releases; the user does that. Local release commit is fine.
- AGENTS.md and CODEX-SETUP.md are the user's untracked files; don't touch.

## Left to the builder

- Restore mechanics: reverse-applying the removal commits per group vs. porting from v0.13.3 /
  v0.14.6 by hand. Either way the result is reviewed against the v0.13.3 behaviour and the later
  fixes.
- Fallback script name and exact output shape.
- Exact metric list for the outcome section, and how the report renderer lays it out.
- CHANGELOG 0.15.0 entry, version bumps in plugin.json/marketplace, `.release-notes/notes-0.15.0.md`,
  and `docs/roadmap.md` updates (mark restored items, record the Verified-org situation and the
  lite plugin as the next project).

## Builder's calls (made by the author during the builder check)

- Restore baseline: start every group from v0.13.3, which contains all of A–D, including
  `needsAuthMcpServers` and the secret-literal flags. (There is no v0.14.6 tag. The 0.14.6
  release is `27f4460`, and the last commit with the flags is `ca3ef7a`.) Every 0.14.x change to
  these files was a removal, a rewording for the scanner, or a non-removal fix. The non-removal
  fixes are ported forward explicitly (see the plan). Before relying on that, the builder confirms
  it by reading each commit in `v0.13.3..ca3ef7a` that touched the flag code.
- Outcome entries for proposals that are not LRN are **report-only**:
  - Never escalate, never remove, and never offer either.
  - Mark them in the ledger, either with a new field such as `outcome_only: true` or with a
    distinct mechanism. The exact shape is left to the builder.
  - Update `ledger.py` validation and `ledger.md`.
  - Ledger files written by 0.14.x must still load.
  - Eligible proposals are COST and SEC items that apply_ops or prune_permissions applied, and
    whose finding has a defined metric.
- Metric values are computed deterministically by a script from the snapshot, never written by
  the model. The metric names, basis, unit and source are fixed in `references/ledger.md` and
  validated by `process_report.py` (or wherever metrics enter the report), so the next audit
  produces comparable values.
- Point-in-time metrics (for example allow-rule count): the window is the snapshot's collection
  time. The verdict is `too_early` when the snapshot was collected before `applied_at`.
- Re-verify restored version-sensitive claims against the current docs:
  - Fetch the raw pages (fetch_doc.py or curl, never a web-fetch summary) and record new source
    dates.
  - Above all, refresh the scope-ignored key tables, the telemetry and tracing env names, the
    mods/`pluginConfigs` options, the `sandbox.credentials` keys and the MCP config fields.
  - Restoring a key list verbatim without that check is a failure.
- Eval cases for restored features: restore them, but don't run them (paid).
- No local tag. The user tags, pushes and releases.
- Root README: correct claims that become false, for example "no network code" or "reads no
  credentials". Otherwise leave it as it is.
- Documentation that restored features touch (checklist, coverage, snapshot-format, drift,
  docs-map, plugin README disclosures) goes back to its pre-removal wording where it still fits,
  else is rewritten accurately. The root README is not changed except for a factual error.
