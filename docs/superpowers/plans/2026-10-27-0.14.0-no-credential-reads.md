# No credential reads (0.14.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The plugin no longer opens credential-bearing files or interprets credential-bearing
values anywhere, so the directory's "reads a credential" hold has nothing to point at.

**Architecture:** `config_names.py` loses every read of `~/.claude.json`, `.envrc` contents and
`env`/`headers`/`oauth` values; it keeps value-free MCP facts (transport, executable, argument
count, package pinning, URL origin/locality) and gains an `.envrc` presence check and a fixed,
non-credential settings-`env` vocabulary lookup. Callers, schema, privacy tables and docs follow.

**Tech Stack:** Python 3.11+ stdlib; `unittest`.

**Spec:** user decisions 2026-10-27 in this conversation, after the 0.13.3 scan kept one plugin-wide
hold ("Something in the plugin reads a credential … remove every part that reads a credential,
which clears this hold"): (1) scope = stop opening `~/.claude.json` and `.envrc` AND stop looking at
`env`/`headers`/`oauth` values anywhere (no literal-vs-`${VAR}` labels, no env/header names); MCP
checks keep server names, transport, URL host and package pinning from `.mcp.json`, plugin and
managed configs; secret-redaction scanning stays. (2) `.envrc`: presence only (stat, no read),
kept for RDY-env-invisible-to-claude.

## Global Constraints

- No obfuscation: no split strings, encodings or misleading names. Docs say plainly what is no
  longer observed and why (the audit does not read credential-bearing files).
- Never open `~/.claude.json` or read `.envrc` contents; never read an `env`, `headers` or `oauth`
  value or enumerate `env`/`headers` names of MCP servers, settings or hooks. Key *presence* of
  `oauth`/`headersHelper` on an MCP config (`configured_mechanisms`) may stay.
- Keep redaction (`LITERAL_SECRET_RE`, `privacy.contextual_search`, `secret-literal-in-rule`,
  `secret-via-env-file`) unchanged.
- No shipped file may pair a credential source name with a URL (`tests/test_shipped_bundle.py`).
- Read-only audit; stdlib; deterministic; fake homes only; never touch the real `~/.claude`.
- Gate (repo root): `python3 -m unittest discover -s tests` and `python3 tests/check_snapshot_schema.py`.
- Commit trailer: `Assisted-by: Claude:<model-id>` only; stage explicit paths.
- No `sleep`/`pgrep` polling loops, no background-then-poll commands. No paid model evals.
- Paths are relative to `plugins/setup-audit/skills/setup-audit/` unless they start with `tests/`,
  `docs/`, `plugins/` or a repo-root file name.

## Rulings (controller)

- Settings `env`: replace enumeration with `config_names.documented_env_set(settings, names)` →
  sorted subset of a caller-supplied fixed name list that are keys of `settings['env']`. Callers
  pass fixed vocabularies: collect.py's `SUBAGENT_ENV` names, and config_checks.py's scope-ignored
  env vocabulary minus any name matching `TOKEN|KEY|SECRET|PASSWORD|PASSWD|CREDENTIAL|AUTH`.
  Snapshot `settings[].env_keys` becomes `env_documented_set` (that subset); `ignored_env_keys`
  keeps its shape but only ever names vocabulary entries.
- `transcripts.mcp_configured_but_unused`: configured = MCP server names the snapshot still sees
  (project `.mcp.json`, plugin, managed); the note says user- and local-scope servers in
  `~/.claude.json` are not read.
- Remove snapshot fields: `global.mcp_user`; MCP server `env_*`, `headers_*`, `oauth`,
  `url_variable_references`, `credential_mechanisms` if it lists values (keep presence-only
  `configured_mechanisms`); user/local-scope MCP rows and `~/.claude.json` project state
  (approval lists, `trust_accepted`); http hook `header_keys` and `allowed_env_vars`;
  `envrc.literal_secret_names`, `envrc.pointer_lines`. `envrc` becomes `{present: true, git}` or
  absent. Add a `limitations` entry: user/local MCP servers live in `~/.claude.json`, not read;
  review them with `claude mcp list`.
- `env.declared` no longer includes `.envrc` names; when `.envrc` is present, `env` gets
  `envrc_not_read: true` so RDY-env-undeclared is reported as "may be declared in .envrc".
- `handler_fingerprint` hashes the handler without `headers` and `allowedEnvVars`.
- Snapshot stays `version: 1`; removals are listed in snapshot-format.md and CHANGELOG as a
  breaking change, so this release is 0.14.0.
