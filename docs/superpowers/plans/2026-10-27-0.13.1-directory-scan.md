# Directory-scan hardening (0.13.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure the shipped plugin so the Anthropic directory's automated checks have no
genuine credential-forward or fetch-and-run pattern to match, without losing audit behaviour.

**Architecture:** The eval suite leaves the shipped plugin folder. Every read of a
credential-bearing config source goes through one names-only module. Docs fetching moves from
`curl` text to a bundled, isolated, fixed-host fetch script. Plus a listing icon.

**Tech Stack:** Python 3.11+ stdlib; `unittest`.

**Spec:** user decisions 2026-10-27 (this conversation): (1) move `plugins/setup-audit/evals/` to
`evals/` at the repo root; (2) one names-only module for credential-bearing reads; (3) bundled
fetch script replacing `curl` instructions; (4) simple generated icon. Directory findings being
addressed: "Update adds credential forward" (files: SKILL.md, evals/README.md,
evals/audit-flags-risky-permissions/fixture.sh, checklist.md, coverage.md, snapshot-format.md,
cache_effects.py, collect.py, config_checks.py, plugin_footprint.py, plugin.json) and
RUNTIME_FETCH_EXEC (evals/README.md, checklist.md, docs-map.md, collect.py).

## Global Constraints

- **No obfuscation.** Never split, encode or disguise words, strings or code to avoid a scanner.
  Every change must be a structural improvement a reviewer would agree with. Plain words such as
  "token" (LLM tokens), "credential" and "secret" stay where they describe behaviour.
- Audit behaviour unchanged: same snapshot fields and values for the same inputs (existing tests
  are the oracle), except where a task says otherwise.
- Read-only audit; stdlib; deterministic; fake homes only; never touch the real `~/.claude`.
- Gate (repo root): `python3 -m unittest discover -s tests` and `python3 tests/check_snapshot_schema.py`.
- Commit trailer: `Assisted-by: Claude:<model-id>` only; stage explicit paths.
- No `sleep`/`pgrep` polling loops, no background-then-poll commands. No paid model evals.
- Paths below are relative to `plugins/setup-audit/skills/setup-audit/` unless they start with
  `tests/`, `docs/`, `evals/`, `plugins/` or `.github/`.

## Review Focus

1. A canary secret placed in every credential-bearing source (MCP `env`/`headers` values in
   `~/.claude.json` user and local projects and `.mcp.json`, settings `env` values, hook `headers`
   values, `.envrc` values) never appears in any return value of the new module or anywhere in the
   collected snapshot. (Task 2 test `test_canary_never_leaves_module`.)
2. A script other than the names-only module that opens `.claude.json` / `.envrc` or reads `env` /
   `headers` *values* is caught by a static guard test. (Task 2 `test_only_module_reads_sensitive_sources`.)
3. The fetch script refuses a non-code.claude.com target, an off-host redirect, a path with `..`,
   and an output path outside the scratch/temp/audits dirs. (Task 3 tests.)
4. Eval tests and the runner-preflight workflow still find the suite at its new path. (Task 1.)

**Interfaces:**
- CLI: `fetch_doc.py PAGE OUT` where PAGE is `llms.txt` or a docs page path like
  `en/settings-reference.md` (regex `^(llms\.txt|en/[a-z0-9][a-z0-9/-]*\.md)$`), OUT a file path
  under a system temp dir, `$TMPDIR`, or `<CLAUDE config dir>/audits`.
- Fetches `https://code.claude.com/docs/<PAGE>` with `urllib.request`, no custom headers beyond a
  `User-Agent: setup-audit-fetch-doc`, no request body, timeout 20 s, max 5 MB, refuses a final URL
  whose host is not `code.claude.com` or scheme not https; writes bytes to OUT (0600, no symlink
  follow); prints `wrote <OUT> (<n> bytes)`; never executes anything; imports no plugin module and
  reads no local file. Exit 2 on bad arguments, 1 on fetch/write failure.
