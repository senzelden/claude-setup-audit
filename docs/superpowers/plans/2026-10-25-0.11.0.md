# 0.11.0 plan — 2026-10-25

Four milestones, user-approved on 2026-10-25, done in this order, one branch each, merged into local
`main`, stopping before push with a prepared 0.11.0 bump. Docs were fetched raw on 2026-10-24/25
(hooks, settings-reference, settings, env-vars, sub-agents, prompt-caching, sandboxing, mods
overview/reference/admin).

Shared rules for every milestone: read-only collection; stdlib only; deterministic; new snapshot
fields are optional and additive within snapshot v1 (`references/snapshot-format.md`), typed in
`references/snapshot.schema.json` where neighbouring fields are typed; every new string leaf is
classified for metadata-only mode in `scripts/privacy.py` (fail closed: unclassified strings are
masked; keep only fixed vocabularies, names, counts and booleans); tests use temporary fake homes
and assert the rule, not today's value, and fail without the change; doc claims cite the page and
fetch date; undocumented transcript shapes are labelled "observed, undocumented" in
`references/coverage.md`. Gate: `python3 -m unittest discover -s tests` and
`python3 tests/check_snapshot_schema.py`. Commit trailer: `Assisted-by: Claude:<model-id>` only.

## Evidence and rulings that shaped the scope

- Ruling: no `shapeHash` cache-break attribution — across 150 local sessions, 35 of 36 main-thread
  `shapeHash` changes were followed by a small cache write, and only 2 big rewrites were
  `unexplained`. The hypothesis is not supported; nothing is claimed about it.
- Ruling: no blob-line skipping — a 30-day real collection takes 13 s / 58 MB; measured, not needed.
- Correction: `prompt_snapshot` attachments are per session start/compaction (2-10 per session),
  not per request; the per-request records are `api-request` (~21% of recent transcript bytes) and
  content-addressed `api-request-blob` (~13%). Format undocumented; the changelog (2.1.29x) says
  transcripts record each request's system prompt, tools and parameters.
- Finding that motivates M1: `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` is set in user settings, yet of
  284 recent subagent spawns Claude passed `model: "opus"` in 100 (those ran Opus 5.5 and are the
  long ones), passed nothing in 55 (ran Sonnet 5.5, the default working), and Explore/Plan/plugin
  agents ran the main model. sub-agents.md "Choose a model": order is per-invocation `model` >
  frontmatter > `CLAUDE_CODE_SUBAGENT_MODEL` > main model (since 2.1.251 the variable is only a
  default; Explore and Plan ignore it); `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` applies it everywhere;
  forks inherit the main model.

## M1 — subagent model mix and request parameters (`feat/subagent-models`)

Collector, inside the existing transcript scan in `collect_transcripts` (window, caps and coverage
unchanged; no extra file passes except one small `.meta.json` read per selected subagent file):

- `transcripts.subagent_models` (measured + observed): per subagent file in the window, read the
  sibling `<agent>.meta.json` (undocumented; keys seen: `agentType`, `model`, `requestShape`,
  `spawnDepth`, `toolUseId`, `description`, `requestNonInteractive`, `finished`). Never read or
  store `description` or `toolUseId`. Bound the read (e.g. 64 KB), refuse symlinks like other
  readers, tolerate absence and malformed JSON (count them). Aggregate rows keyed by
  `(agent_type, requested_model, actual_model)` with `spawns` and `tokens` (input + cache creation
  + cache read + output of that file's assistant usage, deduplicated by message id as elsewhere).
  `requested_model` is the meta `model` string or `null` when absent; `actual_model` is the model of
  the majority of that file's assistant messages. `agent_type` kept verbatim (built-in names and
  plugin agent names are names, kept in metadata-only). Cap rows (e.g. 30) with an omitted count.
  Also `configured`: whether `CLAUDE_CODE_SUBAGENT_MODEL` / `_FORCE` appear in any collected
  settings `env_keys` (names only; never values) — the audit already sees env values only as keys.
- `transcripts.request_params` (observed, undocumented): from `type: "api-request"` records, per
  source class `main` (`repl_main_thread`), `sdk`, `agent` (`agent:*`), `other`: request count,
  counts by `params.model`, by `params.output_config.effort` (null when absent), by
  `params.thinking.type`, and cache breakpoint TTL classes from `cacheControl[].value.ttl`
  (`1h`, `5m` when the value has no ttl — the API default is 5 minutes per prompt-caching docs).
  Only these fixed fields; never system prompts, messages, blobs or hashes.
- Checklist: extend `COST-subagents` (or a new `COST-subagent-model`) to use these: name how much
  subagent spend ran on a top-tier model and why (passed per call vs default vs built-in/frontmatter),
  cite the resolution order and fixes (`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`, frontmatter `model:`
  on custom agents, or CLAUDE.md guidance on when to pass `model`). Effort/TTL rows support
  `COST-cache-health` and `COST-model-default` as evidence; don't invent thresholds.
- Docs: snapshot-format, coverage (undocumented sources and their limits), schema.

## M3 — mods inventory (`feat/mods-inventory`)

- In the plugin inventory (`scripts/extensions.py`, with `harness.py` where plugin hooks are read):
  a plugin whose `hooks/hooks.json` has `modules` (mods reference "Files": an array with one path,
  relative to hooks.json, to an ES module `.js/.mjs/.cjs/.jsx/.ts/.mts/.cts/.tsx`) is a mod. Record
  per plugin component: `mod: {module, exists, bytes, events: [...], calls: [...], truncated}` where
  `events` are first arguments of `on('<event>'` and `calls` are `$.<ns>.<method>` names, from a
  bounded read-only text scan (cap bytes, e.g. 512 KB; never execute; refuse paths outside the plugin
  root and symlinks, as `harness._inside` does). Keep only names matching `[A-Za-z][\w.]*`, deduped,
  sorted, capped. Label the scan heuristic (comments/strings can produce extra names); the docs say
  Claude Code refuses to load a mod whose API use `claude plugin validate` can't read statically.
- Settings: collect `prependPlugins`/`appendPlugins` presence, `allowManagedModsOnly` (managed),
  `disableAllHooks` (already in `other`).
- Checklist `SEC-mods`: mods run unsandboxed with the user's permissions (mods overview "What a mod
  can reach"); weigh `calls` by the admin table (`$.fs.*`, `$.process.*`, `$.http.fetch`,
  `$.env.get/set`, `$.settings.read`, `$.mcp.call`, `$.model.complete`, `$.prompt.submit`,
  `$.session.send`) and events `tool.call`, `tool.check` (can approve; past `ask` rules unless managed
  settings or a Team/Enterprise login), `prompt.submit`, `session.append`, `settings.read`. Point the
  user to `claude plugin validate <dir>` for the authoritative list; never run it from collection.
- Coverage: a `settings.read` mod can rewrite merged settings, so collected files are not the
  effective settings; add that limitation when any mod registers it.

## M4 — `--hash-paths` (`feat/hash-paths`)

- `collect.py --hash-paths` (allowed with or without `--metadata-only`): replace path-like kept
  strings (settings `path`, project roots/keys, plugin roots, file names in inventories — decide the
  exact families from `privacy.py` keep lists and document them) with `h:<12 hex>` =
  HMAC-SHA256(salt, value). Salt: random per run by default (no linkage across audits); optional
  `--hash-salt-file PATH` reads a salt to make hashes stable across runs (the user creates it; if
  the file is missing, fail with a clear message rather than writing it). Same value -> same hash
  within a run so joins still work. Record `coverage.privacy.hashed_paths: true` and which families.
- Check consumers that join on paths (readiness join, config_stacks, drift, compare/report) still
  work or document what degrades; the report renderer must not print the salt.
- Tests: no raw path survives in a hashed snapshot (canary home paths), equal inputs hash equal,
  salt file stability, missing salt file error, metadata-only + hash-paths together.
