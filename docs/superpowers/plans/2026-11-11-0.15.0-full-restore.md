# 0.15.0 full restore: implementation plan

Spec: `docs/superpowers/specs/2026-11-11-0.15.0-full-restore-design.md` (approved).
Execution: subagent-driven. Each task gets one implementer, a review, fix rounds, and the controller
runs the gate (subagent Bash may be refused). The branch gets a final review at the end.

Gate: `python3 -m unittest discover -s tests` from the repo root (920 tests at the start), plus
`claude plugin validate --strict` on the plugin and on the marketplace, both run on a clean export
(`git archive HEAD | tar -x -C "$TMPDIR/..."`).

Session rules for every task: no `rm -rf` and no deleting temp dirs (the user cleans up in bulk), no
sleep/pgrep polling loops, no push, tag or release. Stage explicit paths and use the trailer
`Assisted-by: Claude:claude-opus-5-5`. Leave AGENTS.md and CODEX-SETUP.md alone.

## Task 1: restore the v0.13.3 feature set (spec groups A–D)

The plugin and test files differ between v0.13.3 and v0.14.7 almost entirely because of removals
(`git diff --stat v0.13.3 v0.14.7 -- plugins tests evals`: 21 plugin files, 18 test/eval files).
Method:

1. For each file in that diff, check out the v0.13.3 version. Add back files that were deleted:
   `fetch_doc.py`, `test_fetch_doc.py`, `test_mcp_exposure.py`, `test_mods.py`,
   `test_scope_ignored.py`.
2. Port forward the changes since v0.13.3 that are not removals. Find them by reading every commit
   in `v0.13.3..v0.14.7` that touched those files. The known ones:
   - `0e0a8ec`: fetch_doc test temp dirs get a cleanup, plus the test that checks nothing is left
     behind. This is test-only cleanup, not `rm -rf` in a shell, so it's fine.
   - `8b7b27a`: hook events listed beside JS modules must still be read. Check whether v0.13.3 had
     the same bug. Keep `js_modules_not_scanned` partial only for modules the scanner can't read.
   - The SKILL.md never-open rule (0.14.0/0.14.3 wording). Keep it as a rule for Claude's own
     reads: Claude never opens those files or prints values. Change it so the collector's
     names-only reads are allowed and documented. MCP servers are covered by the collector again,
     and `claude mcp list` stays as optional advice for anything not covered.
   - Step 2 (`b9015ca`): use `fetch_doc.py` again. If raw pages can't be saved, exact keys are
     reported as unverified (keep that rule).
   - `RDY-env-secret-backend`: Claude asks the user every run before probing. The probe reports
     set/unset only and never prints a value.
   - `plugin.json` keeps its 0.14.x shape (no `icon` field, no `direnv` keyword). The version
     bump happens in Task 5.
   - Bug fixes in 0.14.x tests or code that are not removals: port them.
3. `tests/test_shipped_bundle.py`:
   - Remove the scanner-only guards the spec lists.
   - Keep `test_no_evals_in_plugin`, the listing-icon test and `RiskyRulePatterns`.
   - Network guard: the AST import check allows `fetch_doc.py` only, and its host must be the
     constant `code.claude.com`.
   - New value-leak canary: a fake home seeded with sentinel values in settings `env`, `.envrc`,
     `.mcp.json` env/headers, `~/.claude.json` MCP env/headers and http hook headers. A full
     collect must contain none of those values. Red-proof it by stubbing the redaction/names-only
     path.
   - If it still holds, assert that only `config_names.py` (and `extensions.py`, if v0.13.3 did
     this) opens `~/.claude.json` and MCP files.
4. Restore the docs that describe restored features from v0.13.3: checklist, coverage,
   snapshot-format, schema, docs-map, drift, cache-effects, apply-ops and the plugin README
   disclosures. Then fix any text that no longer matches the code. Root README: no changes.
5. Restore the eval case `readiness-envrc-pointers` and `evals/README.md` to v0.13.3.
6. Snapshot version: confirm that version 1 still holds (restored fields are additive/optional)
   against `snapshot_contract.py` and the schema.

7. Docs re-verification (spec "Builder's calls"). The controller fetches the raw pages
   (`settings`, `env-vars`, `mcp`, `sandboxing`, `plugins-reference`, `hooks`,
   `monitoring-usage`, `changelog`) into `$TMPDIR/docs-2026-11-11/` with curl from
   `code.claude.com/docs/en/<page>.md`. The implementer greps them and updates the restored key
   tables and claims, with source date 2026-11-11. Any table entry it can't confirm is marked
   unverified or dropped.
8. Confirm the flag code: read each commit in `v0.13.3..ca3ef7a` that touched
   `prune_permissions.py`, `collect.py` permission flags or `privacy.py`. Port anything that
   isn't a removal.

Commits: one per spec group where practical (A MCP, B env/secret, C scope/mods, D tooling, then
guards). The gate must pass at the end of the task.

## Task 2: names-only collector fallback

- New script `scripts/names_only.py`. Given the same roots as `collect.py` (`--project`,
  `--config-dir`; reuse its discovery helpers), it prints JSON per file:
  - key paths, value types and array lengths;
  - `env`/`headers` key names, never values;
  - permission rule strings redacted with `privacy` helpers (rules are config text the audit
    needs);
  - a status per file: `ok`, `missing`, `not_json`, `symlink_refused`, `too_large`.
- Files: user/project/local/managed settings, project `.mcp.json`, `~/.claude.json` (names
  only), plugin `.mcp.json`.
- SKILL.md fallback: when the collector fails, run `names_only.py`. Claude must not Read settings
  or MCP files whole. CLAUDE.md, memory and rules files may still be Read.
- Add the script to `allowed-tools`.
- Document it in `references/coverage.md` (fallback section).
- Tests in `tests/test_names_only.py`:
  - sentinel values never appear in the output;
  - a malformed file;
  - a symlink is refused;
  - a deep nesting cap;
  - a red-proof check.
- Update the roadmap's "No-credential-reads follow-ups" item.

## Task 3: measured outcome after apply

- Build on `ledger.py`: the `metric` selector already exists. Read the existing metric selector
  code and `references/ledger.md` first.
- Define the supported metrics from existing snapshot fields:
  - context baseline tokens per session (median);
  - cache-miss or cache-read ratio, if collected;
  - permission prompts per session, if collected;
  - allow-rule count.
  
  Pick only fields that exist. Document each one: name, source field, unit, basis.
- Apply flow (SKILL.md, apply section): after a COST- or SEC- proposal with a matching metric is
  applied, record a ledger entry with `mechanism: setting` and a metric selector (or a new
  mechanism value if `setting` doesn't fit). Use the existing `record` path so the baseline comes
  from the snapshot.
- Report: an "Outcome of applied fixes" section, rendered by `render_report.py`/`report_state.py`
  from `trend.ledger` rows that have metric selectors. Each row shows:
  - finding id;
  - applied date;
  - baseline value and window;
  - current value and window;
  - verdict;
  - the existing "comparison of counts, not proof" caveat.
- `too_early` and `unknown` keep their current semantics.
- Tests: record, verdicts across two fake snapshots, and rendering. Red-proof the verdict test.
