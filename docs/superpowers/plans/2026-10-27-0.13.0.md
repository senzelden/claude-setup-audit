# Subscription usage (0.13.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tell a subscriber whether they use their plan well — unused weekly headroom, model-scoped
limit hits, extra-usage settings, early limit resets — from an opt-in status-line log and documented
transcript messages.

**Architecture:** A stdlib status-line command (`rate_limit_log.py`) appends changed `rate_limits`
values to a guarded JSONL log (reusing `drift_log`'s guard). A pure analysis module
(`subscription_usage.py`) turns log entries into window headroom and early resets, and classifies
documented limit-message text. The collector wires both into one optional snapshot field,
`subscription`; checklist items turn it into proposals.

**Tech Stack:** Python 3.11+ stdlib only; `unittest`; JSON Schema file checked by
`tests/check_snapshot_schema.py`.

**Spec:** `docs/superpowers/specs/2026-10-27-subscription-usage-design.md` (read it, including
"Rulings after the builder check").

## Global Constraints

- Shared rules of `docs/superpowers/plans/2026-10-25-0.11.0.md`: read-only audit; stdlib;
  deterministic; additive optional snapshot fields typed where neighbours are; every new string
  leaf classified in `scripts/privacy.py` for metadata-only, path-like ones in a `--hash-paths`
  family; fake-home tests (`tests/test_collect.py::FakeHome`) that assert the rule and fail without
  the change; doc claims cite page + fetch date; undocumented shapes labelled "observed,
  undocumented" in `references/coverage.md`.
- Gate (repo root): `python3 -m unittest discover -s tests` and `python3 tests/check_snapshot_schema.py`.
- Commit trailer: `Assisted-by: Claude:<model-id>` only. Stage explicit paths.
- Log holds numbers and timestamps only: no USD, session ids, model names, text.
- Thresholds are recommendations, not documented limits: 24 h / 1 h staleness, ≥10-point early-reset
  drop from ≥10%, 50% median unused over ≥3 closed weekly windows, <10% family share.
- Never read `~/.claude.json` for this feature. Never infer plan tier or subscriber status.
- No `sleep`/`pgrep` polling loops and no background-then-poll commands (orphaned sandbox processes).
- Paths below are relative to `plugins/setup-audit/skills/setup-audit/` unless they start with
  `tests/` or `docs/`.

## Review Focus

1. Status-line stdin that is empty, not JSON, a JSON array, or has `rate_limits` with null, string,
   NaN or boolean values → logger prints nothing (or only the wrapped command's output), writes
   nothing, exits 0. (Task 1 test `test_bad_stdin_is_silent`.)
2. Log directory unwritable / log path a symlink → status line still prints, exit 0, no traceback.
   (Task 1 test `test_unwritable_log_still_prints`.)
3. Duplicate and out-of-order entries from concurrent sessions → windows grouped by `resets_at`,
   no spurious early reset. (Task 2 test `test_interleaved_duplicates_no_early_reset`.)
4. Assistant prose or tool output quoting `You've hit your weekly limit` → not counted.
   (Task 3 test `test_quoted_limit_text_not_counted`.)
5. A log entry hand-edited with `resets_at` in milliseconds or a non-finite value → that window
   value is skipped and counted malformed, not crashing. (Task 2 test `test_bad_window_values_skipped`.)

### Task 2: Log analysis (headroom, staleness, early resets)

**Files:**
- Create: `scripts/subscription_usage.py`
- Test: `tests/test_subscription_usage.py`

**Interfaces:**
- Consumes: `rate_limit_log.VERSION`, `rate_limit_log.WINDOWS` (log format from Task 1).
- Produces:
  - `read_log(path: str) -> tuple[list[dict], int]` — entries from `path + '.1'` then `path`, sorted
    by `at`; returns `(entries, malformed)`; missing files are empty; tolerant like `drift_log.read`.
    A window value whose numbers are non-finite, bool, or `resets_at` > 10**11 (ms-shaped) is dropped
    and counted in `malformed` (entry kept if any window remains).
  - `STALE_HOURS = {'five_hour': 1, 'seven_day': 24, 'spend_limit': 24}`
  - `analyze_windows(entries: list[dict]) -> dict` — per kind present:
    `{'windows': n, 'closed': n, 'stale_excluded': n, 'peak_used_pct': {'min','median','max'}|None,
      'unused_at_close_pct': {'min','median','max'}|None, 'median_lead_hours': float|None,
      'reached_85': n, 'reached_100': n, 'current': {'used_percentage','resets_at'}|None}`.
    A window is the group of observations sharing `resets_at`; closed when `resets_at` < last entry's
    time; counts toward peak/unused only if its last observation is within `STALE_HOURS[kind]` of
    `resets_at`, else `stale_excluded`. `unused = 100 − last observed` (clamped ≥ 0).
  - `early_resets(entries: list[dict]) -> list[dict]` — events `{'window', 'at' (UTC date),
    'previous_pct', 'new_pct', 'previous_resets_at', 'new_resets_at'}` per the spec ruling: consecutive
    observations of one kind (after dropping exact duplicates and sorting by `at`) where new
    `resets_at` > previous, entry time < previous `resets_at`, previous pct ≥ 10, drop ≥ 10 points.
  - `BASIS_LOG`, `BASIS_RESETS` strings (measured from the opt-in log; upper bound; inferred, resets
    undocumented, account/plan switch or a shared multi-account log look the same).
- [ ] **Step 1: Failing tests:**
  - `test_closed_window_headroom`: three weekly windows last seen 2 h before reset at 30/45/80% →
    `closed 3`, `unused_at_close_pct.median == 55`, `stale_excluded 0`.
  - `test_stale_window_excluded`: weekly window last seen 30 h before reset → `stale_excluded 1`, not in medians; five_hour last seen 90 min before → excluded.
  - `test_current_window`: open window → `current` set, not counted closed.
  - `test_reached_counts`: peaks 86 and 100 → `reached_85 2`, `reached_100 1`.
  - `test_early_reset_detected`: weekly at 60% (resets T+3d) then entry at T+1h with 2% and resets T+7d → one event `previous_pct 60, new_pct 2`.
  - `test_normal_rollover_not_early`: new window first seen after previous `resets_at` → none.
  - `test_small_drop_not_early`: 12% → 5% → none; 8% → 0% → none.
  - `test_interleaved_duplicates_no_early_reset`: same observations duplicated and shuffled → identical result to the sorted run, no events.
  - `test_bad_window_values_skipped`: `resets_at` 1738425600000 and NaN in hand-edited lines → `malformed` counts them, other windows intact.
  - `test_rotated_file_read_first`: `.1` older entries + live newer → entries in time order.

- [ ] **Step 3: Implement** the functions above in `scripts/subscription_usage.py` (`statistics.median`; round to 1 dp).
