# 0.12.0 plan — 2026-10-25

Four milestones from comparing against TokenEconomizer (roadmap "Candidate 0.12.0"), widened by a
survey of common plugins' runtime side effects. User-approved 2026-10-25; one branch each, merged
into local `main`, stopping before push with a prepared 0.12.0 bump.

Shared rules are those of `2026-10-25-0.11.0.md` (read-only; stdlib; deterministic; additive
optional snapshot fields typed where neighbours are; every new string leaf classified in
`privacy.py` for metadata-only and, if path-like, covered by a `--hash-paths` family; fake-home
tests that assert the rule and fail without the change; doc claims cite page + fetch date;
undocumented transcript shapes labelled "observed, undocumented" in `references/coverage.md`).
Gate: `python3 -m unittest discover -s tests` and `python3 tests/check_snapshot_schema.py`.
Commit trailer: `Assisted-by: Claude:<model-id>` only.

## Evidence and rulings

- Survey (2026-10-25): auto-written permission rules are rare (TokenEconomizer deny,
  quartermaster allow opt-in, ClaudeTokenSAP); context injection, hook-supplied permission
  decisions, deliberate fail-open, ms-scale timeouts and spawned child sessions are common. No
  surveyed plugin sets `onFailure`. Evidence and fingerprints:
  `docs/research/2026-10-25-plugin-side-effects.md`.
- Ruling (user): generic signals plus a small dated table of robust fingerprints only.
- Ruling (user): plugin-spawned sessions are labelled, kept in cost (attributed), excluded from
  learning analysis (corrections, friction, tool-error clusters, failure loops).
- Ruling (user): cache effects inform only; apply never holds a change.
- Ruling (user): tool usage is observation only plus MCP failure counts; no deny proposals for
  built-in tools.
- Docs (code.claude.com/docs/en/prompt-caching, fetched 2026-10-25): with tool search active
  (default on supported models) a mid-session bare-name deny keeps the cache; without tool search
  it invalidates. Plugin skills/commands/agents/hooks never invalidate. MCP config edits apply
  after restart. Model, effort, fast mode switches invalidate. CLAUDE.md edits keep the cache and
  apply after /clear, /compact or restart. Permission mode and output style keep it. This
  contradicts TokenEconomizer's blanket idle-wait rationale; we follow the docs.
- Observed, undocumented: transcripts carry `deferred_tools_delta` attachments (`addedNames`,
  `removedNames`, `surfacedNames`, `failedMcpServers` [{name, errorCode, error}],
  `pendingMcpServers`); always-loaded built-in tools are not listed anywhere in transcripts.

## M1 — plugin runtime footprint (`feat/plugin-footprint`)

- Robust fingerprint table in code (dated, cited), per the evidence file. Collector:
  - TokenEconomizer ledger: read `~/.tokeneconomizer/**/untool_applied.json` (bounded depth,
    count and size caps, refuse symlinks, O_NONBLOCK + S_ISREG like `read_agent_meta`; respect
    `$TOKENECONOMIZER_HOME` only if set in a collected settings `env`? no — env values aren't
    collected; use the default path and say so). Map `by_path` realpaths to collected settings
    files; per settings summary record `plugin_written_rules: [{plugin, list, rules: [...]}]`
    for rules present in that file (rules are already kept strings; names only). Rules the
    ledger lists but the file lacks: count only.
  - quartermaster marker key: `plugin_markers: ["quartermaster.autoApprovePermissions"]` per
    settings summary (key path only; the allow rules stay unattributed).
  - Known in-repo/home state files (ralph-loop, hookify, auto-memory, autoharness, claude-hud):
    presence booleans per project / global, names from the table only.
- Consumers: `prune_permissions.py` never proposes removing a plugin-written rule (say why);
  `SEC-*`/`HYG-*` checks label them; the report attributes them.
- Generic signals:
  - Plugin hook handlers on `PermissionRequest`, and PreToolUse handlers whose script (bounded
    static text scan like the mod scan; never executed) contains `permissionDecision` with
    `allow`/`deny`, or `updatedInput`: record `decides_permissions` / `rewrites_input` on the
    handler (heuristic, labelled). Checklist: decisions invisible in rule lists (SEC note).
  - Measured injection per hook source from `hook_additional_context`/`hook_success`
    attachments vs the 10,000-char cap (`over_cap` count): extend `harness_overhead`. Replace the
    superpowers-shaped `skills/using-*` file-size fallback in `plugin_session_start_hooks` with an
    honest "not measured" (or keep but label as a superpowers-specific guess — decide, document).
  - Hook `timeout` > 600 → `HYG-hook-config` issue `timeout_suspect_ms`.
  - Spawned sessions: label sessions whose project path is under `~/.claude-mem/observer-sessions`
    or other robust table entries; verify with fake transcripts. Keep them in cost totals with a
    `plugin_spawned` breakdown; exclude from corrections, friction, tool-error clusters.
- Checklist: new `HYG-plugin-footprint` (or extend existing entries) — what each plugin does
  outside its own files, attributed; fail-open stays SEC-hooks' guard-only concern.

## M2 — cache effect of applied changes (`feat/cache-effects`)

- A table in `apply_ops.py` (or a shared module) mapping every allowlisted op / key family to a
  documented cache effect: `keeps`, `invalidates_next_request`, `invalidates_without_tool_search`
  (bare-name deny), `applies_next_session` (MCP config, CLAUDE.md, keys read once at start such
  as `model`, `effortLevel`, `modelSettings`), citing prompt-caching and settings "When edits take
  effect" (fetched 2026-10-25). Unknown key → `unknown` (fail honest).
- `apply_ops.py --plan` and apply output print the effect per op; `prune_permissions.py` too
  (scoped deny/allow/ask removals keep the cache; bare-name deny changes depend on tool search).
- Estimated cost of one re-read: from `transcripts.cache` median context size and the model's
  cache write vs read price already in the checklist; label as estimate.
- SKILL.md / checklist: each proposal states its cache effect; apply never holds a change.
- Tool-search state: `transcripts.tool_search_observed` (any `deferred_tools_delta` in window) —
  coordinate with M3, which reads the same records; M2 may consume M3's field if M3 lands first,
  otherwise add the boolean itself.

## M3 — tool usage and MCP failures (`feat/tool-usage`)

- From the transcript scan: `transcripts.tool_usage`: sessions with deferred-tool records,
  per tool used-session counts (names; built-in, MCP, plugin), deferred tools listed but never
  used (names capped, omitted count). `tool_search_observed` boolean. MCP: `failedMcpServers`
  per server name: sessions affected and errorCode classes (no error text), `pendingMcpServers`
  counts. Exclude plugin-spawned sessions if M1 merged first, else leave a hook.
- Checklist: `COST-mcp-unused` gains per-tool evidence; deferred tools cost one listing line (say
  so; low priority); a `drift`/HYG signal for MCP servers failing in many sessions (closes the
  roadmap item). No deny proposals for built-in tools.

## M4 — failure loops (`feat/failure-loops`)

- Per turn (user prompt to next user prompt, main thread), detect repeated failing cycles: the
  same normalized Bash command (or test command family) failing ≥3 times, or edit→test→fail
  cycles on the same file ≥3 times. Record `transcripts.failure_loops`: turns scanned, turns with
  a loop, max repeats, tokens spent in looping turns, per project counts, command heads (first
  token class like `pytest`, `npm`; never full commands in metadata-only), session ids capped.
- Ledger signal (`ledger.py`) so a fix's effect can be tracked; checklist `LRN-failure-loops`:
  propose an environment fact for CLAUDE.md, a readiness fix (RDY-test-loop) or a hook; never a
  runtime intervention. Exclude plugin-spawned sessions (M1).
- Calibrate thresholds on fake transcripts; then smoke on the real home (controller does it).
